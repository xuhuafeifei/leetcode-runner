# GraphQL 网络层重构 — 需求分析

> 一句话：将当前基于 Apache HttpClient 的手写 GraphQL 请求层，重构为更简洁、健壮、易维护的 Kotlin 实现。

## 背景

当前网络层存在以下问题：

1. **代码重复**：每个 GraphQL 接口都手动拼接 JSON 请求体、手动解析响应，样板代码多（LeetcodeClient 单文件 900+ 行）
2. **超时严重**：日志中频繁出现 `SocketTimeoutException: Read timed out`，影响用户体验
3. **没有重试**：网络抖动直接失败，用户需要手动重试
4. **错误处理粗糙**：超时、网络错误、业务错误混在一起，用户看到的是 "httpResponse is null"
5. **Apache HttpClient 4.x**：API 冗长，代码量大，维护成本高

## 目标

- [ ] 封装统一的 GraphQL 请求入口，消除重复的 JSON 拼接和响应解析
- [ ] 引入合理的超时与重试机制（指数退避）
- [ ] 更清晰的错误分类与用户友好提示
- [ ] 使用 Kotlin 实现，利用协程、DSL 等特性简化代码
- [ ] 保持对外 API 兼容，业务层（Service）代码改动最小

## 非目标（本期不做）

- 不引入 Apollo Kotlin 等重型 GraphQL 框架（成本高，schema 不公开）
- 不改业务逻辑，只重构网络层基础设施
- 不替换本地 HTTP 服务（LocalResourceHttpServer 等）
- 不涉及文件 IO（StoreService）

## 验收标准

1. 所有现有 LeetCode GraphQL 接口调用正常工作
2. 网络超时错误显著减少（有重试兜底）
3. LeetcodeClient 代码行数减少 30%+
4. 错误提示更友好，能区分"网络超时"、"登录失效"、"业务错误"等
