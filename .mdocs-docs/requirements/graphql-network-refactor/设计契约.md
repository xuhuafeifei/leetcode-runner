# GraphQL 网络层重构 — 设计契约

## 方案摘要

使用 **Kotlin + OkHttp + 协程** 重构网络层，核心思路：

1. **底层 HTTP 客户端**：Apache HttpClient 4.x → **OkHttp**
   - 更轻量（~500KB）
   - 原生支持连接池、拦截器、重试
   - API 更简洁，Kotlin 友好

2. **GraphQL 层封装**：新建 `GraphqlClient` 工具类
   - 统一的 `query<T>(query: String, variables: Map<String, Any?>, clazz: Class<T>): T` 方法
   - 内置重试（指数退避，默认 2 次）
   - 统一超时配置（连接 10s，读取 30s）
   - 统一错误分类与异常抛出

3. **LeetcodeClient 瘦身**：
   - 保留单例结构和对外方法签名
   - 内部委托给 `GraphqlClient` 执行请求
   - 各接口方法只负责定义 query 字符串和变量映射

4. **协程引入**：
   - 网络请求用 `suspend` 函数
   - 现有 Java 调用端通过 `runBlocking` 或回调桥接
   - 逐步迁移，本期先保证能用

## 技术选型决策

### 为什么选 OkHttp 不选 Apache HttpClient？
- OkHttp 更轻量，API 更简洁
- 内置连接池和拦截器机制
- Kotlin 协程友好（OkHttp 4.x 完全支持 suspend）
- IDEA 插件环境下无兼容性问题

### 为什么不用 Apollo Kotlin？
- LeetCode schema 不公开，类型安全优势发挥不出来
- 引入 gradle 插件和代码生成，配置成本高
- 包体积增加较多

详见 [decisions/001-graphql-client选型](../decisions/001-graphql-client选型.md)

## 风险与回滚

- **风险**：协程引入可能对现有 Java 调用链产生影响
- **回滚**：保留旧 HttpClient 代码，出问题可快速切回
